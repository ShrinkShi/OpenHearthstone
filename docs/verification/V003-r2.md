## 新失败：metadata 回调停止后仍启动已停止的调度器

独立归档探针 [v003_r2_checks.cs](../../tools/verification/v003_r2_checks.cs)，入口 `V003R2Checks.Run`。失败使用真实 EX1_134 配置，显式规范化历史为一个尚未完成的 `HistTagChange/type4/tag44`，随后 `HistMetaData/type8/metaType0/metaData0`；真实 `NativeSuperSpellTaskHost` 和 `NativePowerExecution`，两级映射 visual0 → target4 → metadata1。

探针不替换 TaskHost 的结果或原等待配置。仅包裹其 `Bind()` 返回的映射或 Until 判定委托：先调用实际委托得到有效 index/判定，再同步调用根 Cancel 或 Dispose，随后原样返回。这模拟公开历史服务适配器返回期间的主线程重入，不是跨线程操作；实际 TaskHost 的纯 Dictionary 映射/判定本身没有停止回调，正式公开无历史分支也不会自发进入本反例。失败范围是已公开、已支持的显式历史宿主停止契约，不能声称真实 raw transport 或正式 UI 自发复现。

最小复现：

1. 建立上述真实历史宿主，前置 task 未完成，所以 `MetaDataIndex(0)==1`、`ShouldCompleteUntil(1)==true`。
2. 真实刺骨根 `Begin()`，首次零秒等待后调用 `Tick(.01f)`。
3. 在映射或判定服务已得到实际返回值时同步 `Cancel()` / `Dispose()`；停止返回现场为 Cancelled=true、Faulted=false、LastError=null。
4. 让历史回调正常返回，检查 Tick 返回后的 LastError，以及后续服务调用和实际克隆。

期望：干净停止后不调用后续历史阶段、不再启动协程；不产生新的故障或成功。实际最终日志 `work/v003-r2-independent-r3.log`：

```text
272: V003_R2_AT_STOP stage=mapping dispose=False cancelled=True fault=False error=null
291: V003_R2_METADATA stage=mapping dispose=False stopped=True mapped=1 queried=1 until=0 fault=True error=System.ObjectDisposedException
472: V003_R2_AT_STOP stage=predicate dispose=False cancelled=True fault=False error=null
490: V003_R2_METADATA stage=predicate dispose=False stopped=True mapped=1 queried=1 until=0 fault=True error=System.ObjectDisposedException
1137: V003_R2_RESULT passed=38 failures=6
```

Dispose 两组合相同（现场372/571行，结果391/589行）。映射处停止后仍额外调用 predicate 一次；四组合都没有执行 CompleteUntil 委托、创建克隆、完成未执行 task 或发出根 Completed/Finished。6 个失败断言指同一停止检查缺口：4 个错误故障状态、2 个映射停止后的后续 predicate 调用，不是6个独立业务缺陷，也没有图/RT泄漏。

代码定位：`NativeSuperSpell.cs:165–166` 在 `MetaDataIndex` 与 `ShouldCompleteUntil` 返回后没有停止门，直接求值 `clock.Start(Until(metadata))`。Cancel 已 Dispose 该 clock，`NativePresentationCoroutines.Start:27` 抛 `ObjectDisposedException`，由其 Step 捕获并传给根 Fail。`NativeSuperSpell.cs:235` 只过滤停止后的 `OperationCanceledException`，该异常因此成为 LastError。直到167行才检查取消，已晚于调度尝试。Task2 的命中端点在对应 metadata 外部调用后已有停止门；本根的这一遗漏不来自原 IL 对取消的额外保证，而是自主宿主应保持的停止契约。

对照避免把无效历史当产品故障：

- 同一个真实 TaskHost、相同两级映射与未完成前置 task，不注入停止时，真实 PowerExecution handler 执行一次，正常经过原图至 Completed，根 Finished 恰一次，所有记录对象/RT销毁，Execution 完成。
- 在这个真实 PowerExecution 的前置 type4 handler 内直接 Cancel 时，干净停止，无 Faulted、无克隆、无 Completed，后续 metadata task 保持未完成。说明真实 handler 内取消本身可用，失败特指映射/判定服务返回边界。
- 双卡真实工厂 Dispose 后晚返回、首个 Release 抛异常时，失败实例/RT仍归根持有，0 Source/Activate；Dispose/Tick不隐式重试，显式 Cancel 可物理回收，既有故障保留、晚通知不补发成功。
- 双卡工厂返回期间 History.Failed 变真时，晚返回克隆立即纳入根所有权并回收，0 Source/Activate/成功通知。

最小解除条件：在有效历史映射/判定等宿主返回后正确处理停止，避免向已停止调度器发起新派发；保留真正异常诊断，不靠吞掉所有 ObjectDisposedException 掩盖错误。保持正常 metadata Until/From、目标缺失/等待和回收失败显式重试语义。原样重跑本轮和前轮探针、正常根/相关链，再派全新独立验收。验证者未修生产代码。
