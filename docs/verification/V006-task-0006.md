## 忙碌状态与r3证据更正

`work/f006-formal-r3/driver/report.json`在后续操作实际发送时记录：`Busy=false`、`DamageDecorationCount=1`、`nativeActive=false`。这与该时点按钮可用、操作成功相符。独立查看driver逐帧时间线后，发现正式r3运行另有281帧记录`busy=true`、`inputLocked=false`、`damageDecorations=1`；例如frame 6071、runtime time 28.5479s、batchTime 0.8711s、version 7。故TASK-0006原文“`Busy=true && InputLocked=false`仅由RunInputLockChecks覆盖、正式画面未采到”的说法不准确，现已更正。时间线是正式Player运行时状态采样，不是该组合的逐帧截图；07截图及后续`SendMove`发送时的Busy状态仍分别按报告记载。`FireblastReviewChecks.RunInputLockChecks`还独立验证了原生清理仍活跃时的这一状态。
