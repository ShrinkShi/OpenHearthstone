# 本地 UI 校对编辑器

2026-10-10：手牌预览和实战共用设计空间局部旋转，修复窗口缩放后的斜移。玩家名不再继承英雄区域变换，改为窗口左侧锚点；菜单齿轮锚定窗口右侧，原校对 ID 和文件保留。对应交互与转场见 [INTERACTION_LIFECYCLE](INTERACTION_LIFECYCLE.md)。

2026-10-09：战场随从增加原亡语骷髅、剧毒药瓶与扳机闪电独立节点，多机制并排。背景校对按实际 viewport 换算，窗口和预览采用等比矩阵，原配置未迁移或覆盖。窄屏保底与宽屏背景极限见 [WINDOW_FEEDBACK](WINDOW_FEEDBACK.md)。

战场随从预览新增 `minion/taunt` 原版嘲讽盾牌槽，可独立移动/旋转/缩放。预览展示该槽供校对，正式比赛仅 taunt 生效时显示。手牌布局预览与比赛共用 OwnPose：收拢扇形并避让经父/子校对变换后的己方法力计数框，不修改已保存配置。攻击数值默认超过基础值时变绿；“自定义填充颜色”仍可覆盖动态颜色，关闭后恢复游戏状态色。

双击项目根目录 `Start-UIEditor.cmd`。这是现有 Windows 客户端的一个独立校对页面，不需要开启服务器或进入对局。游戏主菜单有“UI 校对工具”按钮；`F6` 打开/关闭，`Esc` 返回游戏。对局中打开编辑器不会暂停服务器，建议在独立编辑器中完成校对。

## 操作

1. 左侧选择随从牌、法术牌、武器牌、装备武器、战场随从、英雄、英雄技能、技能详情卡、战场布局、手牌、换牌、卡背或宝石。共 17 个校对页，含独立护甲和武器耐久图标。
2. 在左下元素列表选择要调整的部分，例如“卡框 / 模型整体”“原画纹理”“名称”“规则文字”“攻击数值”。调整卡牌整体会包含文字和数字；调整原画纹理只修改原画。
3. 拖动橙色中心移动，红色手柄旋转，蓝色手柄缩放。也可先按 `V`、`E`、`R` 切换模式，然后在已选元素上拖动。
4. 右侧可直接输入 X/Y 偏移、角度和 X/Y 缩放，按 Enter 或“应用数值”。保存也会应用尚未提交的有效数值；无效值不会保存。
5. 水平/垂直翻转、+90°、180°用于修正颠倒。原画倒置时选择“原画纹理”，不要把正常文字一起翻转。
6. `Ctrl+Z` / `Ctrl+Y` 撤销/重做；每次鼠标拖动是一个撤销步骤。方向键移动 1 单位，Shift+方向键移动 10 单位。Shift+缩放手柄为等比缩放；“5 单位吸附”用于粗调。
7. 滚轮缩放预览，中键拖动平移预览；预览缩放和平移不保存到对战布局。右侧“复位”恢复预览取景。
8. `Ctrl+S` / “保存”写入配置。返回游戏后，当前实例立即沿用内存中的调整；新启动的两个实例读取保存的配置。已经启动的另一实例按 `F7` 重新读取。

“重置所选”仅删除所选元素的调整；“重置当前页及子元素”清除该页调整，可撤销。战场页重置相机、棋盘和双方区域，保留卡牌模板；手牌页重置双方手牌区域。共享宝石的调整需要在相应宝石页单独重置。

## 分开校对的范围

| 页面 | 可调整内容 | 调整作用域 |
|---|---|---|
| 随从 / 法术 / 武器牌 | 整体、模型、原画 UV、名称、规则文字、费用、攻击、生命/耐久 | 对应卡牌类型全部卡牌，包含手牌、换牌和出牌显示 |
| 装备武器 | 原场上圆框、原画 UV、攻击、耐久、模型部件 | 双方已装备武器；独立 weapon 模板，不修改 card.weapon |
| 战场随从 | 整体、模型、原画 UV、阴影、攻击和生命 | 双方场上的随从 |
| 英雄 | 整体、头像/框、原画 UV、阴影、生命 | 双方英雄及使用同一模板的结算头像 |
| 英雄技能 | 整体、图像/框、原画 UV、费用 | 双方技能 |
| 技能详情卡 | 原始蓝色卡框、圆盘、费用、名称、说明 | 技能悬停详情；实际比赛使用同一绘制函数 |
| 战场布局 | 相机、棋盘、己方/敌方英雄、姓名、护甲、技能、武器、随从区域、牌库、法力区、回合按钮、操作历史 | 各指定区域独立 |
| 手牌 | 己方/敌方扇形整体位置、旋转和缩放；1~10 张预览 | 所有对局的手牌扇形，拖动中的牌仍跟随指针 |
| 起手换牌 | 整体、横幅、标题、牌列、四个牌位、确认按钮 | 实际换牌状态的相同元素 |
| 卡背 / 法力 / 攻击 / 生命 / 护甲 / 武器耐久 | 模型、数字、整体 | 各资源单独模板；护甲与耐久使用专用盾形资源 |

“显示模型内部部件”打开后可直接选择恢复的 MeshRenderer，例如原画网格、标题横幅、卡框、稀有度宝石，以及棋盘可见网格。网格来源路径保持稳定，可单独移动、旋转、缩放/翻转。棋盘部件边框是近似投影占位，不是精确碰撞体；主要从列表选择。场景网格的偏移以设计单位 ×0.015 转为本地世界平面，卡牌网格偏移依据固定取景换算。这里不提供完整的 Unity XYZ 场景编辑器、材质编辑器或资产导出编辑。

卡牌/英雄模板以 320×480 校对单位存储；宝石以 64×64 存储；战场区域使用 1920×1080 设计坐标。尺寸不同的实际实体按比例应用同一模板。手牌区域 X/Y 缩放分别改变扇形分布，卡牌本体使用几何平均的等比倍率；单张卡牌的独立 X/Y 缩放在卡牌模板页设置。

## 保存、备份与交换

默认文件：`E:\HS\HearthstoneClone\local\ui-calibration.json`。与 Profile 分离，Shrink1 / Shrink2 共用同一套校对。保存采用临时文件替换，已有文件保存为 `.bak`。文件包含元素 ID、变换数值及可选文字样式，原版资产没有被修改。

同机两个实例共享此文件；局域网另一台电脑需要把导出的 JSON 放到那台客户端的 `local/ui-calibration.json`，或在编辑器导入后保存。服务器不会传输布局配置。

右下填写 JSON 文件路径后可“导出”或“导入”；导入后先实时检查，再保存。文件格式版本、设计分辨率、重复 ID、非有限数字及缩放范围均会验证，失败保留已有调整。缩放范围 0.05~10。

可使用独立校对文件，避免试验影响正常对战：

```powershell
.\Start-UIEditor.cmd --ui-layout E:\HS\HearthstoneClone\work\trial-layout.json
```

官方参考截图可在右下输入图片路径，点击“参考图叠加”，滑杆调整透明度。图片应匹配当前预览构图；战场截图使用 16:9。叠加仅在编辑器显示，不会加载到对战，也不会随配置导出。

## 验证入口

左侧分类与部件为独立滚动区域，17 类均可访问。战场随从页可选 minion/sleep 调整。技能正背面共用 power 校对；装备武器独立于手牌武器。保留用户最新保存的布局，见 [BATTLE_PACING](BATTLE_PACING.md)。

```powershell
.\.venv\Scripts\python.exe -X utf8 -m tools.ui_editor_capture --counts
.\.venv\Scripts\python.exe -X utf8 -m tools.visual_capture --scenes mulligan,hand4,multiple_minions,minion_attack,hero_power,victory,defeat
```

第一条检查 17 页及 1~10 手牌、1~7 随从，预期输出 34 个场景。构建的 UICalibrationChecks 检查模板隔离、矩阵逆向输入、配置往返、原子失败、撤销/重做、备份和分组重置。新增装备武器页本轮完成构建与离屏模型验证，34 张整页截图未完成。用户游戏时本轮不运行前台截屏入口。

当前限制：编辑器调整空间、方向与文字样式，不编辑动画时间曲线、规则或网络。阴影/状态光圈部分仍是原有程序绘制；死亡等临时效果使用同一实体模板，复杂连锁视觉状态重放的原有差异仍然存在。主菜单木盒按钮的 3D 场景布局尚未接入此校对器。

## 本次实测（2026-10-09）

- Python 规则测试：577 passed，18.73 秒。Unity 构建运行 245 条既有表现断言及 21 条校对断言。
- 实际 Windows Player 输出 30 个编辑器场景，全部为新生成的 1920×1080 图片，退出码正常、日志无运行异常。报告在 `tests/visual/current/ui-editor-final/ui-capture-report.json`。
- 桌面操作验证：整体移动、旋转柄、缩放柄、方向键、撤销、原画独立翻转、重置、保存；新实例加载同一配置。试验变换已从默认校对文件清除。数值输入后直接保存也已验证；快捷键提前于 TextField 处理，避免输入焦点吞掉 Ctrl+S。
- 普通对战 7 个回归场景产生 9 张图，dHash 距离全部为 0。与本项目内部基线比较，英雄技能过程帧像素平均差为 0.007873585，其他帧不超过 0.000005792（0~255）。粒子采样仍有细微差异；此结果不表示与官方画面一致。报告在 `tests/visual/current/ui-runtime/capture-report.json`。
- 双实际客户端自动对局 `f7027ab502ac4387b8d5a7c851a2e7c7`：19 回合、v77，Shrink1 法师胜（1 HP），Shrink2 战士负（-3 HP）；双方状态哈希相同：`6cd3a53e832e44626f17f4dc1e4ad5a3fc60f5142d3e24f5f107ec7f6aba8082`。使用正常匹配与协议动作，不是人工完整比赛。

这些测试确认校对工具和默认对局仍可运行。最终美术位置由用户在编辑器中人工核对；主菜单 3D 布局和动画时序编辑未完成。

后续战斗交互修改保留用户保存的 29 个元素；文件内容及 SHA256 未改变。新增技能详情、护甲、耐久三页，不用生命宝石代替盾牌。调整仍覆盖运行中的默认值，详见 [UI_INTERACTION](UI_INTERACTION.md)。

## 字体、调色板与背景缩放（2026-10-09）

选择元素后切换右侧“字体 / 颜色”，设置填充颜色、描边开关/宽度/颜色、字号、普通/粗体/斜体/粗斜体及阴影颜色/偏移。点击颜色右侧色块展开 RGBA 滑杆和常用色调色板，也可以直接输入 `#RRGGBB` 或 `#RRGGBBAA`。点击“应用字体样式”更新预览，`Ctrl+S` 应用并保存。字号 0 沿用原大小；“清除字体样式”恢复继承。整体的文字样式由子元素继承，子元素独立设置优先，宝石模板也支持同样设置。描述保留数据库的 `<b>` / `<i>` 标签，不能在编辑器逐字修改卡牌规则内容。

生命和耐久默认按状态变色：受损红；满值且上限高于印刷值绿；其余满值白。“自定义填充颜色”覆盖此状态色，关闭即可恢复。描边/阴影可以单独调整而保持状态色。

战场布局页右侧“调整整个战斗背景缩放”选择 `scene.background`，X/Y 缩放控制整个 3D 棋盘和桌面的取景，位置、旋转、翻转也可调整。它不放大英雄、卡牌和按钮；这些仍在各自元素调整。`scene.board` 继续控制模型本身，`scene.camera` 的旧配置仍生效。

战场随从预览新增“扳机闪电”元素，可调整位置/旋转/缩放。编辑器展示该槽供校对，比赛仅有实际监听机制、且未被沉默的随从显示。新验证及限制见 [UI_FEEDBACK](UI_FEEDBACK.md)。
